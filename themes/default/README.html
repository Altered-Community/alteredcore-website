AlteredCore — Theme Development Guide

This guide explains how to create a custom theme for AlteredCore. A theme controls the site's visible navigation (nav.php), footer (footer.php), and stylesheet (style.css). Everything else — security checks, SEO meta tags, Bootstrap, Font Awesome — is handled by the core and does not need to be repeated in a theme.

How themes work

Every page calls includes/header.php (once, at the top). That file does all the heavy lifting:

  • Initialises the session, language, and maintenance check
  • Runs page-access security checks (nav_items, pages visibility)
  • Outputs the complete <!DOCTYPE html>, <html>, and <head> (including SEO meta, Open Graph, favicons, Bootstrap, Font Awesome, theme stylesheet, custom fonts, background)
  • Opens <body> and <div class="site-wrapper">
  • Then calls nav.php from the active theme

At the bottom of each page, includes/footer.php calls footer.php from the active theme, closes the wrappers, and loads Bootstrap JS.

As a theme author, you write nav.php and footer.php. You never touch the page files or the core header.

nav.php — the visible header

When the core calls your nav.php, it has already output <body> and <div class="site-wrapper">. Your file should output the <header> element and the opening <main> tag.

Helper functions

Define these in your nav.php (guarded with if (!function_exists(...))):

// Returns the URL for a nav item (handles iframe items)
if (!function_exists('__nav_href')) {
    function __nav_href(array $item): string {
        if (!empty($item['is_iframe'])) {
            return BASE_URL . '/pages/iframe?nav=' . (int)$item['id'];
        }
        return BASE_URL . $item['url'];
    }
}

// Returns true when a nav item matches the current page
if (!function_exists('__nav_active')) {
    function __nav_active(array $item, string $currentPage, int $iframeNavId): bool {
        if (!empty($item['is_iframe'])) return $iframeNavId === (int)$item['id'];
        $p = basename(parse_url($item['url'], PHP_URL_PATH) ?: '', '.php');
        if ($p === '') $p = 'index';
        return $currentPage === $p;
    }
}

<main>
Important: Your nav.php must end with <main> (open tag only). The page content follows immediately after, and footer.php closes it with </main>.

footer.php — the site footer

At the time footer.php is called, the page content has been output inside <main>. Your footer file should close </main>, output the footer HTML, and close </div><!-- .site-wrapper -->.

The core footer (includes/footer.php) then loads Bootstrap JS and closes </body> and </html> after your file runs.

Variables available in footer.php

All variables set by includes/header.php are still in scope. Use a distinct variable name for footer translations (e.g. $_footerTxt) to avoid colliding with the page's own $txt.

style.css

Your stylesheet is loaded after Bootstrap, the global site CSS (css/style.css), and Font Awesome. You can override Bootstrap variables, use CSS custom properties ([data-theme="dark"] for dark mode), and reference any Font Awesome 6 or Altered Icons class.

CSS load order

The full load order inside <head> is:

  1. Bootstrap 5
  2. css/style.css — global site CSS and CSS variable palette (:root)
  3. themes/{active}/style.css — your theme file (overrides variables and classes)
  4. plugins/{id}/assets/style.css — plugin stylesheet (injected only on plugin pages)

Because plugin CSS loads last, it wins over both the global site CSS and the theme. However, the correct way to theme a plugin is through CSS variables, not direct class overrides.

Required CSS class names

The core generates specific class names on <body> that your CSS should handle:

ClassWhen presentWhat to do
has-bgA background color or image is activeMake .site-header and .site-footer transparent or translucent
page-fullwidthThe active nav item has the full-width flagRemove max-width constraints from <main>'s inner container

Dark mode

The core toggles data-theme="dark" on <html> when the user switches theme. Scope dark-mode overrides with [data-theme="dark"]:

[data-theme="dark"] body {
    background-color: #1a1a2e;
    color: #e0e0e0;
}
[data-theme="dark"] .site-header {
    background: #12122a;
}

Theming plugins via CSS variables

Plugin stylesheets use CSS custom properties defined in css/style.css :root for all theme-sensitive values. To restyle plugin components, redefine the relevant variables in your theme's :root block — no direct class selectors needed for colour changes:

/* themes/mytheme/style.css */
:root {
    /* Override the plugin overlay/modal colour variables */
    --overlay-badge-bg: rgba(10, 8, 28, 0.78);
    --overlay-bar-bg:   rgba(10, 8, 28, 0.68);
    --overlay-qty-bg:   rgba(10, 8, 28, 0.82);
    --modal-panel-bg:   rgba(255, 255, 255, 0.65); /* glassmorphism */
    --panel-border:     rgba(255, 255, 255, 0.7);
    --mobile-nav-bg:    rgba(255, 255, 255, 0.88);
    --mobile-nav-border: rgba(255, 255, 255, 0.7);
}

/* Dark mode — same approach */
[data-theme="dark"] {
    --overlay-badge-bg:  rgba(12, 10, 32, 0.85);
    --modal-panel-bg:    rgba(28, 30, 55, 0.98);
    --card-lightbox-bg:  rgba(10, 8, 28, 0.88);
}

Properties that cannot be expressed as CSS variables (e.g. backdrop-filter) still require direct class selectors in the theme file.

head-extra.php — optional <head> additions

This file is included by the core inside <head>, just before </head>. Use it to inject theme-specific styles or scripts that must live in the document head.

Typical uses

  • Navbar-width CSS driven by the navbar_width admin setting
  • Additional body classes via $__extraBodyClasses
  • A secondary web font or icon library

Example head-extra.php

<?php
// Navbar width — translate admin setting to CSS
$_navbarWidth = getSetting('navbar_width');
if ($_navbarWidth === 'full'):
?>
<style>
.site-header{width:100vw;margin-left:calc(50% - 50vw);}
</style>
<?php elseif (is_numeric($_navbarWidth) && (int)$_navbarWidth > 0): ?>
<style>
.my-nav-inner{max-width:<?= (int)$_navbarWidth ?>px;margin:0 auto;}
</style>
<?php endif; ?>
<?php
// Inject an extra body class consumed by includes/header.php
if ($__mobileCompact) {
    $__extraBodyClasses   = isset($__extraBodyClasses) && is_array($__extraBodyClasses)
                            ? $__extraBodyClasses : [];
    $__extraBodyClasses[] = 'my-mobile-compact';
}
?>
Font selectors: The core targets .site-header, .site-header .dropdown-menu, and .site-footer for custom fonts. If your theme uses different selectors, add overrides in head-extra.php using the same SiteFont_font_nav / SiteFont_font_user_menu font-family names declared by the core.

Installing a custom theme

  1. Upload your theme folder to themes/{slug}/ on the server.
  2. Go to Admin → Themes — your theme appears automatically.
  3. Click Activate. On first activation the theme inherits the default theme's settings as a starting point.
  4. Configure colors, fonts, background, and logo via the normal admin settings pages while your theme is active.
Theme file fallback: If a file is missing from the active theme, themeFile() falls back to themes/default/. This means head-extra.php is completely optional — if absent, the core skips it.
