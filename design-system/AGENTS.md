# Design system — rules for coding agents

Read `README.md` (what is where, how each technology uses it) and `WORKFLOW.md` (design → code)
before changing anything under `design-system/` or building a screen.

- `tokens/tokens.css` is the only file with raw values. Adding a token means a light value and a
  dark value (`:root[data-theme='dark']`), and a touch value if it depends on the density.
- Components (`css/components/`) use tokens only and never test `data-theme` / `data-density`:
  they are injected into SPA shadow roots, where `<html>` selectors do not match.
- Hover styles go in `@media (hover: hover)`, keyboard focus (`:focus-visible`) outside it: on
  touch screens `:hover` sticks to the last tapped spot until the next tap.
- Class names: `ac-<component>`, `ac-<component>__<part>`, `ac-<component>--<variant>`. States
  use ARIA attributes (`aria-pressed`, `aria-current`, `aria-selected`, `aria-invalid`,
  `:disabled`) rather than classes when a native attribute exists.
- Every component change updates, in the same commit: its CSS, `docs/components/<family>.md`,
  `pages/design-system.php`, and the framework components that render it
  (`plugins/rebuilder/app/src/app/ui/`).
- Icons: Lucide names. `icons/*.php|svg|css` are generated by `icons/build.mjs`: edit `fa-map.json`
  or the script, then `npm ci && npm run build` in `design-system/icons/`, never the outputs.
- Bridges (`css/bridges/`) exist for pages not migrated yet. Do not add new legacy names; when a
  page is migrated, it uses `ac-*` classes and `--ac-*` tokens directly.
- PHP helpers (`php/ui.php`) must stay PHP 7.4 compatible (production runs php:7.4).
- After a change: `php tests/run.php` (Docker: `docker compose exec web php tests/run.php`), then
  look at `/pages/design-system` in both themes.
